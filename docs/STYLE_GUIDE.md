# HELLBOUND style guide

The rules that keep the game looking like one game and the code easy to find your way around.
When something new is added, it should follow these. When a rule changes, change it here first.

## 1. Screen and pixels

| Thing | Size | Where it's set |
|---|---|---|
| The game screen | **640 × 360** game pixels, scaled up by a whole number to fill the window so pixels stay square | `LW`, `LH` in `js/core.js` |
| One tile of the world | **32 × 32** world pixels | `T` in `js/core.js` |
| A tile on screen (isometric) | a **32 × 16** diamond. A world point (x, y) is drawn at ((x − y) / 2, (x + y) / 4) | `isoScreen()` in `js/render.js` |
| Wall height | **30** screen pixels | `WALL_H` in `js/render.js` |
| HUD and menus | built in HTML on top of the canvas; `calc(var(--u)*N)` means N game pixels | `css/hellbound.css` |
| Map size | up to **72 × 72** tiles | `MW`, `MH` in `js/core.js` |

## 2. Colours

All colours have names in `js/style.js` (`COL.blood`, `COL.gold`...). Use the name, not the hex code.

| Group | Names | Used for |
|---|---|---|
| **Blood** | `bloodDark` `#6e0d18`, `blood` `#8f1a1f`, `bloodHi` `#c4302c`, `bloodLit` `#e05a4a`, `bloodPale` `#ff8a7a` | the main colour: wounds, the vat, the altar, danger |
| **Gold** | `goldDeep` `#b48a34`, `goldWarm` `#e0bf68`, `gold` `#ffe14f` | rewards, the way forward, legendaries, UI titles |
| **Fire** | `fireDeep` `#a12a06`, `fire` `#ff6a1a`, `ember` `#ff7a2b`, `fireHi` `#ffd27a` | Fire Line, embers, lava, torches |
| **Bone and ash** | `bone` `#d6cab2`, `boneLo` `#a89a84`, `text` `#c9a99a`, `ash` `#5d5059`, `ashDark` `#4a3f48` | text, stone, dust |
| **Magic** | `volt` `#9ef0ff`, `voltDeep` `#5ad8ff`, `arcane` `#8fa8ff`, `perk` `#ff8ad8`, `voidC` `#b46bff`, `danger` `#ff4f6e` | one colour per kind of power, so a fight can be read at a glance |
| **Outline** | `ink` `#0a0608` | the 1 px outline around every sprite |

**Rule of thumb:** red means blood or danger, gold means reward or "go here", blue-white means electricity,
pale blue means stardust, pink means perks. Don't reuse a meaning colour for something else.

## 4. Art rules

- **Light comes from the top left.** Highlights go up and left, shadows down and right.
- **Every sprite has a 1 px dark outline** (`COL.ink`).
- **Colour ramps of 5 to 7 steps**, dark to light, blended with a 4 × 4 ordered dither (`bayer4()` in `js/eye.js`, `bayer()` in `tools/art/pix.py`).
- **Noita influence:** things that move a lot are drawn live, pixel by pixel, instead of from a sprite sheet: the Oculus, lightning, sparks, lava and blood pools, the vat. Sparks bounce, and lightning lights up the room.
- **Warnings before damage:** every big enemy attack shows where it will land first (red lanes and circles, blue rings for electricity), with enough time to roll out.
- **Readable at a glance:** if something matters (a drop, a warning, the way forward), it gets a dark halo or a light so it shows on any floor.

## 5. Code layout

- **One job per file** in `js/`. The README lists them. Files load in the order in `index.html` and share one global scope.
- **Each file starts with a comment** saying what it does and how the pieces fit.
- **Numbers you might tune go at the top of the file in CAPITALS** (`FLASK_MAX`, `SPIN_CD`, `VAT_SHARE`, `COMBO_WINDOW`...), each with a comment.
- **Comments say why, not what.**
- Hand-made art is generated by Python scripts in `tools/art/` (`py tools/art/build_art.py`); licensed art is imported by `tools/art/import_thirdparty.py` and credited in `CREDITS.md`.
- Every change is checked by `tests/smoke.mjs` on GitHub. Add a line there for each new feature.

## 6. How to add...

- **A monster:** add its stats to `ET` in `js/data.js`; give it a sprite sheet (`tools/art/monsters.py`) or a live drawing (like `js/eye.js`); give it an AI function in `js/enemies.js` and hook it up in the enemy loop in `js/update.js`; give it a letter in the level legend (`ENEMY_CH` in `js/world.js`).
- **A level:** copy `levels/blood_altar.js`; the map is plain text, one character per tile, with the legend at the top of that file.
- **A sound:** write a synth recipe in `audio/sfx.js`, or list recorded files in `SOUND_FILES` there (see `audio/README.md`).
- **A perk:** add a line to `PERKS` in `js/perks.js`, then put its effect where it matters using `hasPerk('name')`.
- **A colour:** add it to `COL` in `js/style.js` and to the table above.
